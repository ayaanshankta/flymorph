A rebuild course for Ayaan

FlyMorph, built twice

A TypeScript app that measures Drosophila larvae and adult flies in mm² from your stereo-microscope photos. It uses classic image processing for larvae and a small neural network, distilled from Meta’s Segment Anything, for adult head, thorax and abdomen. Every chapter below is one git tag. Read it, close it, rebuild it in an empty folder, then compare.

767adult photos indexed, 44 duplicates dropped
63 / 75scale images calibrated automatically
0.90body Dice on flies from unseen sessions
47unit tests on the TypeScript core

How to use this course

  1. Make an empty repo. For each chapter, read Goal and Concepts, then build it yourself.
  2. Stuck? Read the Key code, or run the checkpoint command to see exactly what changed in that step.
  3. Do the Try it yourself task. That is where you actually learn it.
  4. Read the Pitfalls. Each one happened while building this, on your real images.

The shape of it

flowchart LR
  scale[scale.jpg] --> cal[calibrate: FFT of ticks → px/mm]
  larva[larva.jpg] --> lp[larva pipeline: threshold → morphology → components]
  adult[adult.jpg] --> net[FlyNet ONNX × 8 MC-dropout passes]
  cal --> m[Measurements mm² ± SD]
  lp --> m
  net --> m
  m --> web[React app: overlay, table, CSV]
  m --> cli[Node CLI: folder → CSV]
  photos[767 adult photos] --> sam[SAM drafts] --> review[your review] --> train[train FlyNet] --> net

Everything in packages/core is plain TypeScript over typed arrays: no DOM, no Node APIs. That is why the same code runs in a browser tab, a Web Worker and a Node CLI.

Pixels as numbers

m02-image-io

Goal. Load a photo into a flat array you can loop over, and draw it on a canvas.

Concepts

  • An image is width × height × 4 bytes (red, green, blue, alpha). Pixel (x, y) starts at index (y·w + x)·4.
  • HSV value = the brightest channel. Larvae are bright on a dark cloth, so V separates them from the background.
  • Separable blur. Blur rows, then columns: 10 multiplies per pixel instead of 25.
  • The browser decodes with createImageBitmap + canvas; Node decodes with sharp. Both hand core the same RGBA layout.

Try it yourself

Write toGray using the luminance formula 0.299R + 0.587G + 0.114B, with a test. Compare it with toValue on a larva photo: which separates larva from cloth better?

Checkpoint: git diff m01-scaffold m02-image-io

Measuring larvae without ML

m03-larva

Goal. Photo in, one area per larva out. This is the classical computer-vision pipeline, and every step is about 20 lines you can read.

Concepts

  1. Otsu threshold. Try all 256 cut-offs and keep the one that best splits the histogram into two groups.
  2. Morphology. Opening (erode, then dilate) deletes specks. Closing (dilate, then erode) bridges small gaps.
  3. Fill holes. Flood the background from the border; background the flood can’t reach is a hole inside a larva.
  4. Connected components. Give every touching group of pixels an id, and record its area, box and centre.
  5. Shape filters. Minimum area in mm², elongation, fill ratio. Then solidity (area ÷ convex hull) flags blobs that aren’t larva-shaped.

Pitfalls hit while building this

  • The old fixed threshold under-measured. segment.py kept pixels with V > 95. On mefsp_norm food_2.jpg, that cut into the translucent head and flanks, and the bites open to the outside, so fill-holes can’t repair them. Otsu chose 75 and follows the real edge; areas came out 7–15% larger. The old CSV also counted two specks as larvae.
  • “Merged?” by size was wrong. A rule of “bigger than 1.8× the median” flagged a single, genuinely big larva. Solidity works better: real singles scored 0.84–0.98 across 38 images. Every blob under 0.8 was a larva fused with the orange tape strip in the 260212 photos.
  • Dark head tips get missed. The mouth hooks show through as a dark notch at the front, which slightly under-measures some larvae.
  • Test order. Components are numbered in raster order (top row first). Two tests expected the wrong order, and the code was right.

Try it yourself

  1. Fix the orange-tape problem: drop pixels whose HSV saturation is high and hue is orange before thresholding. Check mch_standard.jpg loses its irregular flags.
  2. Fix the dark tips: after filling, take each larva’s convex hull within a few pixels of its outline. Measure how much the areas change.

Checkpoint: git diff m02-image-io m03-larva -- packages/core

Reading the scale bar with an FFT

m04-calibration

Goal. Turn the stage-micrometer photo into pixels per millimetre automatically. The old code had (2178 - 1500) / 1.0 hardcoded, with the auto-detection commented out.

Concepts

  • The micrometer is a 1 mm bar with a tick every 0.01 mm, longer ticks every 0.05 mm and 0.1 mm. Evenly spaced ticks are a periodic signal, and the Fourier transform finds periods.
  • Average a band of rows into a 1-D brightness profile, remove slow lighting changes, window it, FFT it. The tallest peak is the tick spacing p, and px/mm = ticks per mm × p.
  • Which rows? Scan every band and keep the most periodic one. Texture and the dark ring are not periodic, so a faint bar still wins.
  • Which ticks? The bar is exactly 1 mm long, so (periodic stretch ÷ period) must be 100, 20 or 10. That both picks the tick set and rejects impostors.

Pitfalls hit while building this

  • A larva photo passed as a scale. Larval body segments are periodic too. Version 1 returned 3903 px/mm with confidence 38. The length check (a 1 mm bar must span 100 ticks) now rejects it.
  • Faint bars on foam. Picking the row with the most edges chose the foam texture; picking the most periodic row fixed it.
  • Widening the search broke everything. Allowing periods up to 150 px let low-frequency lighting win in 58 of 75 images. Low frequencies always carry more energy, so the range went back to 3–40 px.
  • Result: 63 of your 75 scale images calibrate automatically, with zero false accepts. Images from the same session agree (every vGat scale gives 1256–1261 px/mm). The other 12 are blurry low-zoom bars that fall back to two clicks.

Try it yourself

Write fftMag yourself (radix-2 Cooley–Tukey) and test that a cosine with 5 cycles peaks at bin 5. Then plot the spectrum of a real scale image’s profile and find the 0.01 mm and 0.05 mm peaks by eye.

Checkpoint: git diff m03-larva m04-calibration

The web app

m05-measure-ui

Goal. Drop a photo and a scale image to get an overlay, a table and a CSV, without the page freezing.

Concepts

  • Web Worker. A 10-megapixel image takes about 4 s of pixel loops. A worker runs them on another thread so the UI stays responsive. Vite bundles it from new URL('./worker.ts', import.meta.url).
  • Transferable buffers. postMessage(msg, [labels.buffer]) hands memory over instead of copying 40 MB.
  • Canvas overlay. Paint the photo, tint labelled pixels, draw boxes. CSS scales the canvas, and clicks convert back to image pixels.
  • Errors people can act on. Scale bar not found? Show the scale image and ask for two clicks.

Pitfalls hit while building this

  • The first Measure click did nothing because the button was disabled while the 7 MB JPEG decoded. The button now reads “Loading image…”.

Try it yourself

Accept several larva photos at once and show one table with a file column. The worker already handles one image, so loop it.

The Node CLI

m06-cli

Goal. flymorph larva ./folder --scale scale.jpg produces one CSV for a whole imaging session. That’s what the lab actually runs.

  • node:util parseArgs handles flags with no dependency. sharp decodes images.
  • One bad file doesn’t kill the batch: failures are listed at the end and the exit code is 1.
  • Same core, same numbers: the CLI and the web app give 0.39334 mm² for the same larva.

Try it yourself

Add --overlays out/, which writes each photo with its larvae outlined (sharp can composite a PNG mask).

Labels: SAM drafts, you decide

m07-labels

Goal. Get about 60 correct head/thorax/abdomen masks without painting a single pixel by hand.

headthoraxabdomen

Concepts

  • Foundation model as teacher. Segment Anything (SAM) outlines almost anything you point at, but it is ~375 MB and needs prompts. We generate the prompts automatically.
  • Automatic prompts. Find each fly by colour saturation, get its long axis from pixel moments, and find the head end from the eye (redder than that fly’s own body). Then place points at 8% / 35% / 72% along the axis. Each part’s point is positive and the other two are negative, so SAM splits the parts.
  • Human in the loop. The review page shows each draft. A approve, R reject, X fly is backwards, or click and press F to re-prompt one part. Only approved masks are ground truth.
  • Body-plan rules as a free check (Ayaan’s idea). Order: the thorax sits between head and abdomen, so from its centre they point opposite ways (negative dot product). Gap: head and abdomen touch the thorax; a wide gap means the mask missed body in between (measured with a chamfer distance transform). Sizes: the head is the smallest part. Pieces: no part splits into two big halves. On the 94 approved photos these rules raise 0 false alarms; on the unapproved drafts they flag 12 of 60. The drafter retries a fly that breaks the order rule, and the review page asks twice before approving a fly that breaks any rule.
  • Sessions. A session is the nearest folder holding a scale image, because everything calibrated together was photographed together. Top and side views of the same flies are one session.

Pitfalls hit while building this

  • About 1 in 8 drafts had the fly backwards; orange-eyed flies failed a fixed “red hue” test. The fix compares against the fly’s own body colour and adds the X key.
  • 44 photos were byte-identical copies in different folders. Content hashes (SHA-1) catch them, where folder names can’t.
  • pip quietly installed numpy 2, which broke the conda scipy that transformers imports. The fix is numpy<2 in requirements.
  • MPS (the Mac GPU) has no float64; SAM point tensors must be float32.

Your turn, for real

Run ml/.venv/bin/python ml/draft_server.py and npm run dev, open #/review, and approve 60. Expect about 15 minutes per 50.

Training the student

m08-model

Goal. A 1.66 M-parameter U-Net that reproduces your approved masks on flies it has never seen, and is small enough for a browser.

Concepts

  • U-Net. The encoder shrinks the image into features, the decoder grows them back into a label per pixel, and skip connections carry fine edges across.
  • Transfer learning. The encoder is MobileNetV3-small pretrained on ImageNet. It already knows edges and textures, which is why about 60 labels can be enough.
  • Loss = cross-entropy + Dice. Cross-entropy alone is dominated by the background, which is about 90% of pixels; Dice scores overlap per part.
  • Split by session. Photos from one session are near-copies. Random splitting would put siblings in train and test and measure memory instead of skill.
  • Dropout as an input. The bottleneck is multiplied by a drop tensor. That keeps the ONNX graph deterministic and moves the randomness to TypeScript.

The model in the browser, with error bars

m09-adult

Goal. Run FlyNet on the user’s own GPU and report each part as area ± uncertainty.

  • ONNX Runtime Web tries WebGPU first and falls back to WebAssembly. The CLI loads the same file with onnxruntime-node.
  • Monte Carlo dropout. Run 8 passes, each with a random 20% of bottleneck channels switched off. Where the passes agree, the model is confident. The spread of the 8 areas is the ± you report.
  • Body-plan flags. Each predicted fly is checked with the same rules as the review page and flagged order?, gap?, sizes? or pieces?. Mask pieces within 12 px are grouped, so a fly with a gap is still measured as one fly.
  • Letterboxing. The model sees a 512×512 square. preprocess shrinks and pads, and every area is scaled back by 1/scale² into original pixels, then into mm².

Pitfall hit while building this

The plan defined each fly from the averaged prediction, then counted every pass inside that region. That hides the disagreement the error bar is supposed to show. A test caught it: a fly the passes disagreed on came out with SD 0. Flies are now the union of all passes.

Try it yourself

Check the error bars are honest: on the test set, about 95% of true areas should fall inside ±2 SD (coverage_2sd in the metrics). If far fewer do, the model is over-confident. Try more passes or a higher drop rate.

Ship it

m10-ship
  • npm run build makes a static site in apps/web/dist, which GitHub Pages can host for free. The model runs on the visitor’s machine, so there is no server to pay for.
  • The README leads with a GIF of the app measuring a real fly, then quickstart, then the honest limitations.
  • Rebuild this site with node site/build.mjs. It re-reads the code, so the excerpts can’t go stale.

Known limitations

  • Touching flies are measured as one fly, and larvae touching background objects are flagged but not fixed.
  • The scale image must use the same zoom as the photo; nothing can check that for you.
  • The model is trained on one lab’s microscope and backgrounds. New setups need a few new labels.

ML deep dive

Why not just use SAM in the browser?

SAM is ~90 M parameters and needs someone to click on every part of every fly. FlyNet is 1.66 M parameters and needs no clicks. It is a specialist: it only knows flies, and that is all we need. Training a small specialist on a big generalist’s outputs is knowledge distillation. The human review in the middle stops the student from learning the teacher’s mistakes.

Why segmentation and not detection?

A detector draws a box around a fly. We need area, so we need the exact pixels of each part. A per-pixel classifier (semantic segmentation) gives that directly, and connected components split the pixels into individual flies.

Why error bars?

A phenotype paper compares mean body size between genotypes. A blurry or folded fly measured confidently wrong adds noise you can’t see. With MC dropout, each measurement carries its own uncertainty, so you can flag or down-weight doubtful flies instead of trusting them equally.

How the numbers are kept honest

  • Only human-approved masks count as ground truth. Draft-trained models are labelled as such everywhere.
  • Test sessions are held out whole, and overlap is checked by content hash, not by filename.
  • Test Dice above 0.98 prints a leakage warning. A number that good is a bug until proven otherwise.
  • Coverage of ±2 SD checks the error bars themselves.

Interview prep

The 60-second version

“My lab measured fly body size by thresholding photos by hand, with a hardcoded scale. I rebuilt it as a TypeScript tool. Larvae use a classical CV pipeline, and I found the old fixed threshold under-measured by 7–15%. Calibration reads the stage micrometer automatically with an FFT. For adult flies I used Segment Anything to draft head/thorax/abdomen masks, reviewed them myself, and distilled them into a 1.66 M-parameter U-Net that runs in the browser on WebGPU and reports each area with a Monte Carlo dropout error bar. One core library powers both the React app and a Node batch CLI.”

Likely questions

Why TypeScript for an ML project?

Training is Python (PyTorch), because that’s the right tool. Inference and everything around it (calibration, measurement, UI, batch CLI) is TypeScript, so it runs anywhere with no install and no server. ONNX is the bridge between the two.

How do you know the model is accurate?

Dice and median area error on imaging sessions the model never saw, against masks I reviewed. The split is by session and checked by content hash. I also check that ~95% of true areas fall inside ±2 SD.

What was the hardest bug?

Scale calibration. Larval segments are periodic, so a larva photo passed as a “scale” at 3903 px/mm. The fix uses the physics of the object: a 1 mm bar spans exactly 10, 20 or 100 tick periods. That check rejects impostors and tells you which tick set you found.

What would you do next?

Separate touching flies (instance segmentation or a watershed on the body mask), add wing area, and use active learning: send the flies with the largest error bars to the review queue first.

What is knowledge distillation?

Training a small model to reproduce a big model’s outputs. Here the big model (SAM) plus human review produced the labels, and the small model learned them well enough to run in a browser tab.
